# 我把 Qwen3.8-27B 接进 Pi 和 Claude Code，能干活，但没那么顺

我最开始只想确认一件事，64GB 的 M2 Max 能不能跑 Qwen3.8-27B。答案是能。

我在 Ollama 里装的是 qwen3.8:27b-mlx，模型文件大约 18GB。第一次短对话总共用了约 14 秒，其中加载模型约 11 秒。后来我又丢了一张界面截图给它，它能读出页面结构，也认出了底部正在使用的模型。聊天和看图这两项都跑通了。

但这台机器当时并不轻松。活动监视器里，Ollama 进程占了约 20.43GB，整机已用内存约 61.67GB，交换空间用了 19GB。那时微信、浏览器、开发工具和其他程序也都开着，所以不能把整机负载全算到模型头上。在我的实际工作环境里，它不是一个随便挂在后台都没感觉的模型。

接下来我用 ollama launch pi 把模型接进 Pi。第一次启动会检查 Pi、安装 @ollama/pi-web-search，然后读取本地的规则和 Skill。启动日志里还出现了一条 Skill 名称冲突提示。它能启动，但环境并不干净。

我先让它照着本地调研规则查 Qwen 新模型。它确实会按要求找 Agent Memory、AnySearch 和 Agent Reach。Agent Memory 当时不可用，它跳过了；几条搜索命令又因为参数写法不对，直接返回 code 2。后面它换了更简单的命令继续查，没有彻底卡死。

模型知道要读规则、调工具，发现失败后也会换办法。可它连续查了六分多钟，命令稳定性一般，还一度把 2026 年的搜索结果当成可能来自未来。录屏结束时，它仍没有交出一份干净的最终结果。

我更难接受的是速度。之前一个只让它读取当前目录的简单任务，上下文有 7,742 个 token，它等了约 66 秒才开始调用工具。工具返回后，第二轮两秒左右就结束了。时间主要花在第一次处理规则、Skill 和工具说明上。

我又让 Pi 做了一个前端页面。最开始只说“帮我生成一个前端 Web 页面”，它没有马上堆代码，而是先问用途、页面类型、技术栈和风格。这一步我觉得是对的。我把需求缩成单文件个人博客后，它写入 blog/index.html，再打开浏览器预览。

从 Pi 启动、来回确认需求，到浏览器出现成品，这段录屏约 8 分半。页面有搜索、分类和明暗主题，作为练习 Demo 可以交差。视觉还是很常见的 AI 博客模板，里面的内容也是临时编的。这次只写了一个 HTML 文件，没有改现有项目，也没有跑测试，不能拿它证明模型已经能负责真实开发。

最后我试了 Claude Code。Ollama 的 Launch 页面直接给了 ollama launch claude，接入本身很方便。第一条消息一直没有返回，我手动中断后，界面出现 502 status code (no body) 并自动重试。

这次用下来，我会继续把 Pi 留作本地模型的练习入口。它慢，工具命令也会犯错，但至少完成过读图、搜索、调用 Shell 和写文件。Claude Code 这条路连第一条消息都没有稳定跑完，我暂时不会用它做主力。

所以，对这台 64GB M2 Max，我的回答不再只是“27B 能跑”。它能跑，也能做一点 Agent 工作；机器繁忙时负担不小，长上下文首轮很慢，工具和兼容性也还需要继续调。拿来研究和做小 Demo 可以，替代我平时用的云端 Agent，还差一截。
