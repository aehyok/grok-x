## 正文

我们一直把 LLM 当锤子用在每个 AI 问题上，包括简单决策。Jev 用毫秒级、零头成本接住这些决策。TypeSafe 2026-09-15 发布 Jev，一个不能聊天、不能写代码、写不出有用段落的模型却引起异常强反应。限制本身就是点：多数软件不需要另一个 chatbot，需要成千上万次小判断——工单急不急、哪个模型接手、这条 shell 危险吗、这段检索是否回答了问题。

每次判断丢给通用 LLM：逐 token 生成、解析、校验、形状不对再试。五个可能答案的决策来说又慢又贵。Jev 专为这些决策：非结构化 state 进，类型化答案和概率出。

最短准确描述：语义决策引擎。三种原语 Choice / Score / Noul。程序保持控制，所以有人叫它 smart switch statement：普通代码拥有分支，模型提供普通代码算不稳的模糊判断。

TypeSafe 说同一请求里的问题并行评估。官方端到端 70–500ms，$0.042/百万输入、输出免费。头条「200 倍快、400 倍便宜」来自自建工作流评测，当上限看，不当每个应用的承诺。底层优势仍可信：它避开长推理轨迹和生成输出。

概率重要：billing 赢了但很险时不该自动路由。高置信自动、中等确认或更强模型、低的给人。阈值写在代码里。RLCD 目标是置信度反映准确率。

「不能幻觉」只在窄定义下成立：不能返回 schema 外选项，不能产出畸形散文。但仍可能自信地选错一个合法选项。更安全的句子：Jev 不能打破声明的输出 schema，但仍可能错。

三个特别有说服力的位置：模型路由；工具风险门（只读/可逆/破坏性）；验证与监督（测试过了吗、是否在重复同一动作）。

今天能解的问题共享三点：能叫出可能答案、细心人能很快判断、决策频繁到延迟或成本要紧。客服运营、搜索重排、质量安全、海量分类、实时界面。Jev 目前只文本，环境要先转成文本/JSON。

不该用：答案空间未知；写回复/摘要/代码/解释；算术计数日期；多跳隐推理；抽未知值；无关上下文太多。有确定代码就别上模型。

落地：选一个有界低风险决策 → 先写 rubric → 收集含模糊和对抗的例子 → shadow mode → 按数据设阈值 → 先自动化最安全分支 → 版本化问题和阈值。
