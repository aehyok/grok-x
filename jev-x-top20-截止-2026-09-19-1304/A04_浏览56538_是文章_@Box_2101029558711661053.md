## 正文

作者 @olga_stefaniuk。卡尼曼《思考，快与慢》：System 1 快、直觉；System 2 慢、审慎。软件用 AI 也可以这样想。LLM 应用常做成聊天界面，开放推理时合适；工作流常常先需要一个能被代码检查和使用的快判断。

Jev 是 TypeSafe 的旗舰 System One 模型。概览页的说法：把它想成前沿智能的函数调用——非结构化 state 进，类型化概率决策出。它放弃文本生成，换取事先定义好可能值的类型安全输出。每个答案带概率和置信度，软件能区分清楚判断和不确定判断。输出并行生成，适合直接坐在应用逻辑里：分类、路由、打分、抽取、校验、分支。

三种原语：Choice、Score、Noul。没有 prompt-to-JSON，也没有再把解释转回程序值。

Demo：把事故管理文档经 System One 分流到 Escalate / Monitor / Review 三个文件夹。Severity、Escalation 概率、Incident type 写成 Box 元数据。若判为升级，再创建任务通知人审。Box 当版本化内容接口，Jev 当语义决策层。

流程：Box Python SDK 拿 PDF 的 Markdown 表示 → 带三条类型化问题发给 Jev（每问含 instruction 和详细标准）→ 应用按阈值路由。Jev 处理普通代码处理不好的「乱自然语言」；策略、阈值、权限留在应用里。

自己试：免费 Box 开发者账号 + TypeSafe waitlist + clone 仓库并上传示例 PDF。激活环境、跑 setup 建元数据模板、填 developer token，可选创建 review task。成功后文件被移动、元数据写入、升级则建任务。

小闭环：Box 保管文档和历史，Jev 把非结构化内容变成类型化概率决策，应用把信号变成可检查的智能 if。
