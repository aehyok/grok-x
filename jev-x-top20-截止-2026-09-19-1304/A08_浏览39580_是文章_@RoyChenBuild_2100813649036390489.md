## 正文

双向编码器，还是去掉生成环的因果解码器？

2026-09-18。Jev 提出一个架构问题：一个返回决策而不是文本的 API 后面，坐着哪种预训练模型？TypeSafe 描述：接收 state、questions、预定义答案空间，返回类型化结果和概率。RLCD 被写成从预训练语言模型出发的后训练路径。公开材料没有点名底层 checkpoint。

两种假说：BERT 式双向编码器；被改去预测、不再走自回归生成环的因果解码器。这是架构假说，不点名模型家族，也不证明权重来源。

Archer Hume 约 1 万次 API 调用后，提出：共享 state 计算、隔离 question 分支、直接读概率的因果 transformer，并怀疑 MoE。他自己也承认实验区分不了因果解码器和双向编码器。

假说一：为通用决策任务建的双向编码器。BERT 模式：双向注意力处理文本，再用表示做分类。Jev 接口允许请求时定义问题和选项，所以需要能解释新标签描述的机制，而不是输出神经元永远等于 billing/sales/support。LLM2Vec 说明「原本当解码器训」和「现在当双向编码器跑」可以同时成立。

假说二：在文本生成开始前就停下的因果解码器。Hugging Face 已有 Llama 的因果 LM 和 sequence classification 版本。OpenJev（TheoLeeCJ/openjev）用冻结的 Qwen3.5-4B，一次前向，只对指定大写答案 token 的 logits 做 softmax，不采样、不进生成环，还支持共享 state prefill + 并行 question 分支。另一个 AlexWortega/openjev 用 last-token pooling + 三分类 NLI 头。这些证明可行性，不是 TypeSafe Jev 的架构或 checkpoint。

去掉生成环并不自动变成 BERT 式编码器：因果 mask 仍在。并行预填与因果注意力兼容。对 Jev 接口，因果注意力的实用优点是可复用 state 计算：文档在所有问题前面，表示不依赖后面的问题文本，可算一次。Hydragen 提供共享前缀注意力的工程先例。

校准是独立问题。两种架构都能输出分布，也都能自信地错。作者目前更倾向「为直接决策改过的因果解码器」，因为好复用预训练语言能力和共享前缀计算。要在两者间下结论，需要注意力模式和训练史披露。
