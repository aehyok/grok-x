## 正文

Agent 在一个循环里跑：LLM 决定下一步、工具执行、模型评估结果，直到任务完成。Agent 和 LLM 一开始很难嵌进依赖结构化数据、可预期接口的软件。后来有两个原语把这件事变容易：

- Tool calling：让模型发出结构化请求、收回结构化结果
- Structured outputs：让模型返回结构化结果

但即便如此，agent loop 仍然又慢又贵：每个决策都要再调一次模型。

这时 Jev 来了。Jev 是 TypeSafe AI 发布的新模型。公司报告在分类任务上，推理最多快 200 倍、成本低 400 倍。

这篇文章讲 Jev 怎么工作、它在 agent loop 里放哪、以及怎么和 LangChain 一起用。

### All about Jev

Jev 其实不是传统 LLM，它不生成文本。TypeSafe 称之为 System One 模型：

> System One models 是一类为软件直接使用而建的 AI 模型，做快速、结构化决策。它评估一段 state，返回类型化答案和概率。

训练方法是 RLCD（面向校准决策的强化学习）。代码用这些结果引导 agent 下一步，而不必为每个决策打一通完整聊天 LLM。

调用时送入 state（上下文）和关于这段 state 的 questions。文档里客服工单的单问题例子：urgency 答案可以是 99.9% 紧急，应用拿它做优先级。

三种问题类型：

- **Choice**：从选项里挑。返回每个选项的概率 + 整体置信度
- **Score**：按你定义的有序等级打分。返回连续分数、底层分布、置信度
- **Noul**：是否题。返回命题为真的概率

关键：同一段 state 可以一次问多个问题。System One 并行评估请求里的每个问题。加问题几乎不改响应时间，只多付那些很便宜的额外 question token。

总结：不像传统 LLM，Jev 既不受文本生成约束，也不做串行决策。

### How to Use Jev with LangChain

LangChain 的 provider-agnostic 模型很适合把 Jev 和几千个其他集成放在一起。集成通过 `TypeSafeClassifier` 暴露 Jev：把 state 和 questions 传给 `.invoke()`，拿到的是分类结果而不是聊天回复。

装 `langchain-typesafe`，设 `TYPESAFE_API_KEY`，然后调用。state 可以是文本、结构化数据或 LangChain messages。所以很容易从已有 agent 上下文的 node 或 middleware hook 调 Jev。也可以做成自定义 middleware 或 tools。

### Use Cases

Jev 不是 LLM 的即插即用替代。它不生成文本，但能接住我们今天常用 LLM 做的分类，而且没有同样的延迟和成本。它更适合当驱动 agent 的那个模型的互补：开放推理和生成走 LLM，沿途的快速结构化决策走 Jev。

**Model routing**：简单查找不需要和困难调试同一个模型。路由 middleware 让 Jev 评估请求、按你定义的标准选模型：简单任务走快且便宜的，复杂任务走更强的。概率和置信度也留在 agent state 里。

**Auto Mode**：Agent 仍然不可完全信任。坏指令（自然产生或攻击者）可能说服它做我们不想做的事。Claude / Codex / Cursor 这类 coding harness 已经用某种方式在危险动作执行前分类，慢慢建立信任。此前这层分类锁在 harness 的闭源部分。现在有了便宜且能打的分类模型，同一模式可以套到所有 agent。`AutoModeMiddleware` 用 Jev 检查 tool call 的风险，在工具执行前拦截。

我们对 Jev 以及它带来的可能性很兴奋。已经看到的项目：Browserbase 的 Kyle Jeong 用几分钱跑 browser use agents；Jarrod Watts 做了实时交易 agent；Ryan Vogel 在规模上做邮件分流。

## 原文

Agents run in a loop: an LLM decides what to do, a tool executes, a model evaluates the results, and then continues in that loop until the task is complete.

Agents and LLMs were initially difficult to integrate into software applications, which depend on structured data and predictable interfaces. Two primitives emerged that made this much easier:

Tool calling let models make structured requests and receive structured results.

Structured outputs let models return structured results.

But even with those in place, the agent loop is still slow and costly: every decision requires another model call.

Enter, Jev. Jev is a new model released from TypeSafe AI. The company reports up to 200x faster inference and 400x lower cost than comparable LLMs on classification tasks.

This post covers how Jev works, where it fits into the agent loop, and how to use it with LangChain.

Jev is actually not a traditional LLM, it doesn’t generate text. It’s what the TypeSafe AI team calls a System One model: a class of AI models built to make fast, structured decisions that software can use directly. A System One model evaluates a state and returns typed answers and probabilities.

It’s trained using reinforcement learning for calibrated decisions (RLCD). Your code uses those results to guide what an agent does next, without a full chat LLM call for each decision.

There are three types of supported questions: Choice, Score, Noul. System One models evaluate every question in a request in parallel.

LangChain exposes Jev through TypeSafeClassifier. Use cases include model routing and AutoModeMiddleware that checks tool calls for risky decisions before execution.
