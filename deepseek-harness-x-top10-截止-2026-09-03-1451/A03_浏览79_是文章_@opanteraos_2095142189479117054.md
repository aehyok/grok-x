## 正文

作者 2026-09-02 实测：GitHub 209,127 star / 24,397 fork。官方正确命令是 `npx @deepseek-ai/dsh web`。

两个坑：

1. `npm install -g deepseek-harness` 会装到一个 581 字节的占位包（dsh-tui），不是官方仓。供应链风险。
2. 在 3.8 GB RAM 沙箱里跑 `npx @deepseek-ai/dsh --version`，V8 heap 顶到约 1.9 GB 后 OOM。加 `NODE_OPTIONS=--max-old-space-size=1500` 同样崩。`--help` 一样，176–228 秒后挂。包当时是 0.1.1-rc.2。

官方 SAFETY.md：developer preview，未做安全审计，能跑模型生成的命令、加载第三方插件、碰网络/进程/凭据/文件。建议丢弃式 VM/容器、最小权限、先审插件和命令。

结论：20.9 万 star 量的是好奇和转发速度，不是生产成熟度。插件优先架构值得试，但要先在最紧的机器上跑最简单的命令。

## 原文

Eu instalei o DeepSeek Harness para testar a arquitetura de plugins que todo mundo está elogiando. O comando mais básico, só para checar a versão, derrubou o processo por falta de memória antes de imprimir uma linha. Isso não invalida o projeto, mas muda o que vale a pena testar antes de colocar em produção.

O que é o DeepSeek Harness e por que 209 mil pessoas deram estrela
DeepSeek Harness, ou dsh, foi lançado pela DeepSeek AI em 13 de agosto de 2026 como developer preview. Em uma semana já tinha 165 mil estrelas no GitHub. Quando testei, em 2 de setembro, o repositório estava em 209.127 estrelas e 24.397 forks, uma curva de adoção mais rápida que a do Claude Code em proporção de tempo, e com zero issues abertas no momento da checagem, o que por si só é um sinal de projeto muito novo, não de projeto maduro. A tese central é simples de enunciar: em vez de um agente de código com funcionalidades fixas, como Codex ou Claude Code, o DSH constrói tudo, interface de chat, injeção de contexto, chamada de ferramenta e até o próprio loop do agente, como plugins substituíveis. Isso é diferente de um agente com sistema de extensões. Aqui a extensão é o agente inteiro. A base técnica é o Cordis, um meta-framework descrito no paper "A Programming Paradigm for Spatiotemporal Composability" (arXiv 2608.25512), que formaliza efeitos reversíveis e coeffects reativos para software dinâmico, disponível em arxiv.org/abs/2608.25512. Na prática, cada comportamento discreto do harness, desde como uma pergunta de esclarecimento é feita até como um botão renderiza na interface, é uma unidade que pode ser trocada em um painel de configuração sem tocar no núcleo. Existe um marketplace de plugins de terceiros e um modo criador que guia a construção de um plugin novo dentro de uma conversa, sem escrever a extensão à mão. Um exemplo citado pelos primeiros usuários é o ModLens, um plugin que dá visão a um modelo que não processa imagem nativamente, roteando a imagem para outro modelo e devolvendo uma descrição em texto, e há também uma visão de trajetória que audita qual plugin disparou qual chamada de ferramenta, algo que a maioria dos agentes de código fechados não expõe. O DSH também suporta delegação para sub-agentes, chamando Claude Code ou Codex de dentro de uma sessão quando a tarefa é mais adequada para esses modelos, o que é uma admissão honesta de que plugin-first não significa superior em tudo, apenas mais transparente sobre onde cada parte do trabalho é feita.

Eu tentei instalar e travei duas vezes antes de achar o comando certo
A primeira armadilha nem é técnica, é de nomenclatura. Rodei npm install -g deepseek-harness seguindo o nome óbvio do projeto e instalei um pacote real, publicado há três semanas, mas que é apenas um placeholder reservado para um projeto diferente, o "dsh-tui", com 581 bytes e nenhum código funcional. O pacote correto, documentado no README oficial, é escopado: npx @deepseek-ai/dsh web. Isso é um risco de supply chain real e nada exótico: qualquer pessoa seguindo o nome intuitivo do projeto instala silenciosamente outra coisa. Depois de corrigir o comando, tentei npx @deepseek-ai/dsh --version no meu ambiente de sandbox, com 3,8 GB de RAM total. O processo cresceu o heap do V8 até perto de 1,9 GB e morreu com "Ineffective mark-compacts near heap limit Allocation failed - JavaScript heap out of memory". Repeti com NODE_OPTIONS=--max-old-space-size=1500 para forçar um teto menor e o resultado foi o mesmo erro, só que batendo no novo teto em vez do padrão. Testei --help no lugar de --version para eliminar a hipótese de que o problema fosse específico de um subcomando, e o comportamento se repetiu de forma idêntica, sempre entre 176 e 228 segundos até o crash. Isso não é uma falha de sintaxe nem de rede, é consumo de memória sustenido em algo que deveria ser trivial, o que sugere que a resolução de dependências do pacote ainda em release candidate (0.1.1-rc.2) não foi otimizada para ambientes de RAM restrita, como containers e VMs pequenas, que são exatamente onde agentes autônomos costumam ser hospedados por segurança.

O que o aviso de segurança do próprio projeto diz, e por que ele importa mais que a estrela no GitHub
O arquivo SAFETY.md do repositório é direto: "DeepSeek Harness é software experimental de developer preview. Não passou por auditoria de segurança e não deve ser tratado como seguro ou pronto para produção." O texto continua dizendo que o projeto pode executar código e comandos gerados por modelo, carregar plugins de terceiros e acessar rede, processos, credenciais e arquivos disponíveis para ele, e que sandboxing e prompts de aprovação reduzem risco mas não garantem isolamento. A recomendação explícita do próprio time é rodar em VM ou container descartável, com privilégio mínimo, manter backup dos arquivos acessíveis ao projeto e revisar plugin, configuração e comando proposto antes de deixar qualquer coisa executar sem supervisão. Nenhuma dessas frases aparece na cobertura que celebra as 209 mil estrelas, e é exatamente esse tipo de aviso que costuma ficar de fora quando a métrica de sucesso de um lançamento é velocidade de estrela por hora em vez de tempo em produção sem incidente.

Conclusão
Minha posição é que 209 mil estrelas em três semanas medem curiosidade e velocidade de compartilhamento, não maturidade operacional, e a arquitetura plugin-first do DeepSeek Harness é genuinamente interessante o suficiente para justificar testar, mas só depois de replicar as restrições reais do seu ambiente de deploy. A pergunta que vale guardar antes de adotar qualquer agente com esse volume de hype é: você testou o comando mais simples do projeto na máquina mais restrita que vai realmente usar, ou só confiou no contador de estrelas do GitHub?
