## 正文

GPT-6 Astra 出来之后，X 上一下子多了这些报告：「现有 Codex 环境全换成 Astra 了！」「reasoning 拉高真离谱！」「转几十分钟，整个项目就完成了！」

懂，Astra 确实是怪物。OpenAI 官方也把它写成最强模型，编程、调研、电脑操作、复杂多步作业都大幅加强，上下文 105 万 token。

但有一个很关键的问题：现在流传的 Astra 用法，大量混进了月付约 3 万日元的 Pro 玩法。月付约 3000 日元的 Plus 照抄，通常会变成：哇 Astra 好强 → 跑几个任务 →「已达使用上限」。文明结束。

OpenAI 自己也写了：Plus 在 ChatGPT Work 和 Codex 里只有「有限用量」的 Astra，而且 Astra 有时比 GPT-5.6 Sol 更快消耗额度。消耗还跟任务大小、输入输出、reasoning、Fast mode 有关。API 参考价：Sol 输入 $4 / 输出 $20（每百万 token），Astra 输入 $10 / 输出 $50，正好 2.5 倍。ChatGPT Plus 额度不能直接按 API 价换算，但「拿 Sol 那套喂巨大上下文、长时间推理，会很重」这个感觉要有。

所以这不是让你抠着花 Astra，而是反过来：能用的次数有限，更要把每一发的工作量拉满。

前提：按 2026-09-07，Plus 用户 Astra 官方主要在 ChatGPT Work 和 Codex。Plus 的游戏是：有限的 Astra 框怎么用。

① reasoning 基本固定 low。medium / high / xhigh / max 很诱人，但 Plus 每任务都开满，浪漫和额度一起烧。Astra 开 low 不会变蠢，底座就是 Astra。普通实现、调查、整理文件、改现有代码、浏览器、做资料，先 low；不行再抬。例外是「以后要用几十上百次的底座」，比如 Codex 初始搭建、AGENTS.md、目录、规范、测试方针——开头少花一点，后面 100 个任务都低效 10%，更亏。目标不是 token 最少，是每个成果的 token 最少。日常 low，重要设计 medium，真难再往上。Plus 每次 max，等于开法拉利去便利店。

② 别把现有项目原样切到 Astra。Sol 时期养了半年的巨型 AGENTS.md、规则、旧日志、说明书、Skills、子代理、「以防万一」的 `instructions_backup_final_v2.md`，每次全塞给 Astra，输入必然很重。能装 105 万 token，不等于每次都该喂 105 万。冰箱能塞 100 瓶啤酒，也不用每晚喝 100 瓶。Sol 最优的 harness，不一定还是 Astra 最优。以前用长提示、细规则、大量知识、多层代理补模型不足；Astra 这么强以后，harness 堆太厚会反过来把强模型用得很贵。建议新建一套 Astra 专用轻量环境，而不是只换模型名。

③ 现有项目要用 Astra，请它当改造者，不当每天的短工。类似曾用 Fable 的方式：不是 100 个日常任务都开 Astra，而是一次扔给它：「看完整项目，把没用的 instructions、重复规则、多余知识、冗长工作流清出来，按现在的模型能力重做成最小构成。」一次 Astra，可能让后面 100 次 Sol/Terra 都变轻。常驻 1 万字 AGENTS.md 若能砍到 2500，其余按需再读，后面一直省。

④ 用「能完成这活的最轻执行环境」。比 10 个站做对照表，不必拉起本机仓库、终端、MCP、Skills、子代理整套 Codex。浏览器活，ChatGPT Work 的 Cloud Browser 往往够：读页面、点击、填表、登录站点、汇总资料。做文档、表格、演示也一样，Astra 官方也加强了这些交付。以前是「模型不够，用提示补」；现在是「模型太强，把多余提示删掉」。

⑤ 别让 Astra 干「作业量」，让它干「难度」。30 条 X 文、改格式、改错字、给 CSV 分类、改文件名、定型报表、方针已定的代码量产，Sol / Terra / 有时 Luna 就够。OpenAI 现在的定位：Astra → 最难的端到端；Sol → 高级专业活；Terra → 能力与成本平衡；Luna → 高频、看成本。Astra 该接的是：人想 2 小时也定不了的架构、从大量信息里找出真问题、跨多个应用的复杂电脑操作、从含糊规格做到成品、Sol 反复卡死的 bug、大量视觉判断的制作、设计新工作流本身。Astra 定完方针之后的「按同样格式再做 30 个」，交回 Sol/Terra。脑子用 Astra，物量用下级模型。

半年叠规则叠到六法全书的项目，不妨借 Astra 从零按最小构成重建，往往比改遗产更轻。Plus 的 Astra 不是「常用」，是「一点突破」：一天 100 次还行的 AI，和真正关键时召唤 5 次怪物，是两种打法。Plus 选后者。从今天起：先把 Astra 设成 low；别把巨型旧项目直接塞进去；把活分成「只有 Astra 解得了」和「别的模型也能做的物量」；后者不用 Astra。有余力就让 Astra 审计一次 Codex，把「以防万一才放进去的上下文」删掉。需要的目标、硬约束、判断用材料还是要留。
