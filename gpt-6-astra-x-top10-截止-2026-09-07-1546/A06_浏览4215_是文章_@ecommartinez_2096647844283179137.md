## 正文

你可以花几小时试提示词。也可以学会给 AI 一份「结果能核对」的工作：打得开的网页、审得了的分析、编得了的 3D、来源查得到的调研。本指南讲怎么跟 GPT-6 Astra 合作：怎么开始、它需要什么工具、怎么下指令、早期演示说明什么、怎么评估交付。含 20 条可改的原创提示。

1. Astra 是什么，变了什么

GPT-6 Astra 面向多阶段复杂工作。OpenAI 强调推理、编程、调研和用软件。官方指南也写：对指示更敏感、更常澄清提问、小任务上核对有时过长。作者建议：定义一份能检查的交付。「调研我的市场」留下太多未决；「比较这五家公司，交一张表，含价格、目标客户、差异点和来源」才是可评估的活。贯穿全文的规则：每个委托都要有「做完了」的证据。

2. 模型、环境和工具

看任何演示，先拆三件：模型理解任务、产出回答或动作请求；环境是你从哪个应用工作，决定有哪些文件、程序、控件；工具用来查信息或执行动作。电脑使用里，集成层执行请求的动作，再把截图送回给模型核对状态。实践后果：开口「改我的 Blender 项目」之前，先确认文件在哪、这环境能不能跑 Blender；开口「分析我的销售」之前，先给数据或接上源。

提示 01：先核对起点。完成【目标】之前，先列出本会话需要哪些文件、来源、工具；分清这里能执行什么、什么必须我来；缺必不可少的东西只问那一件；然后做能做的，标出未完成部分。

3. 怎么开始

ChatGPT Work 输入框下的选择器里选模型和档位。能不能用取决于部署、账号和客户端。Codex CLI 文档示例是 `codex -m gpt-6-astra`。文档页上有模型，不证明你的账号能用。第一次建议：选一件真实小工作；附上材料并说明每个文件是什么；定义交付（表、文档、代码或图）；加两三条验收标准；看第一版，要一次具体修正。好练习是把乱笔记变成工作计划。

提示 02：把这些笔记变成一页计划，分开目标、已做决定、任务、负责人、日期；缺信息写「待定」；核对每项任务都来自笔记；文末列出最有助于具体化的三个问题。Astra 不在选择器里，去查账号。一句「请表现得像 GPT-6」替代不了选模型。

4. 怎么写有用的委托

官方建议写目标、上下文、输出和边界，只给相关信息。作者模板再加明确验收。提示 03 母版：目标是给【受众】的【具体结果】。以【文件或来源】为底。交付【格式和篇幅】。遵守【约束】。当【可核对标准】满足时视为完成。次要决定用合理假设并声明。缺的信息若会实质改变结果再问。交之前对照标准检查。弱标准：「看起来专业」。强标准：「报告含一条建议、三个可比方案、每个价格带链接」。提示 04 控风格：给谁看、什么语气、先写主旨、短段、删空赞美、保住数字和来源。

5. 上下文

API 卡：105 万 token 上下文，最多 12.8 万输出，知识到 2026-04-30。输入文本和图像，输出文本；音视频不在原生模态。可以用工具，包括生图。上下文是一次请求能用的材料，不是永久记忆。准备文件时写清哪个文件说了算、哪版已批准、哪些过时。提示 05：先审附件，标出版本、矛盾、缺失；不要用编造填洞。答得像那么回事，不证明它上过网。

6. 推理档

从默认档起，需要再加。文档有 Light/Low、Medium、High/Extra High、Max；Ultra 用子代理。实验性上下文管理默认关。短变换先轻；多约束比较用中；架构或难调研再抬。API 有 low / medium / high / xhigh / max，没有 none。

7. 两个已公开案例

Void Explorer：Thomas Ricouard 用 Astra 在 Codex 做的游戏，2048 个星系、1 万+ 行星，TypeScript / Vite / Three.js，有测试和人工审查。这是作者发在 OpenAI 站点上的案例，不是本文独立复现。Solace：同一作者让 Astra 用 Python 在 Blender 建房子、加家具、做灯光相机，还进过 UE5。作者声明这是可视化，不是施工图。两例同一人，不能外推一般成功率。提示 06 做能玩完的小网页原型；提示 07 做一间可编辑工作室加两台相机。

8. 从数据到决定

提示 08 分析 CSV：先认字段、查重复缺失、能算再算、观察和假设分开、总额和原文件对上。人审应抽查数字。提示 09 做成六页演示，数字必须与批准版一致。提示 10 对照原委托逐条验收，不要用自己上一句当证据。

9. 提示 11–20

竞品调研、写 X 文前先核实、newsletter、可评估落地页、修具体 bug、带诊断的家教、只基于所给文档对比、按政策起草客服回复（不外发）、设计可重复流程、把好会话收成别人能用的程序。

10. 怎么改、不必整单重来

修正要指出故障，以及必须保住的属性。交付太泛就加可接受样本。因次要决定停下，就写清可以假设什么。它改了已批准部分，就再点名并要求保住。要文件却给了计划，就写死格式。API 的 mid-turn steering 可在回答中途加要求，但不撤销已做动作，也不取消已启动的工具。

11. API

标识符 `gpt-6-astra`。应用必须自己提供工具、数据和控件。有结构化输出、流式、缓存、compaction、多智能体编排；可用 configuration_update 改推理强度。欧盟数据驻留下没有 Fast mode。async tool calling 适用于应用侧函数，不适用于托管内置工具。集成前用一小套代表性任务记录对错、时间、成本。

12. 价格

2026-09-06 标准 API：每百万 token 输入 10 美元、缓存命中 1、缓存写入 12.50、输出 50。输入超过 272,000 token 整单加乘数（输入和缓存 2×，输出 1.5×）。Batch/Flex 半价，Fast 为 2×。简化例子：1 万输入无缓存 + 2 千输出 ≈ 0.20 美元，未含工具。比较方案时把重试、中间调用、审查时间也算进去。每 token 价不是 ChatGPT 订阅价。

13. 限制

引了来源也可能解错，打开原文核对。图好看不证明有可编辑文件。计划不等于执行。答得长仍可能不完整。接上了不等于能访问一切。精选演示测不了一般可靠性。后果大的活，核对必须匹配决定。

14. 练习

第一场提示 02 + 真实笔记。第二场提示 05 + 两份熟文档。第三场本业练习，开始前先定三条标准。第四场提示 10 审交付。第五场提示 20 留下方法。选一件一直拖的活：清楚入口、具体交付、一种核对办法。Astra 有用的部分从这里开始。
