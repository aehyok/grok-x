## 正文

OpenAI 发布了 GPT-6 Astra，并建议大家重新检查 AGENTS.md 和 Skills。

但这并不是在说：

「Skill 已经没用了」
「大量买来的 Skill 全浪费了」
「用 Astra 之前必须先把 Skills 删掉」

这些说法被夸大了很多。

看 OpenAI 官方 Model Guidance，实际写的是：Astra 比以往模型更擅长跟随指示（instruction following），对 Skills、AGENTS.md 里的指示也更敏感，因此强烈建议审计模型会读到的 Skills 和各类文件。

OpenAI 的 Victor Nunez 也发帖说：「Astra 开始铺开的现在，正是重新整理 AGENTS.md 和 Skills、再考虑 reasoning level 用法的好时机。」

重点是：这不等于「把 Skills 删掉」。

会出问题的是这些东西：

- 给旧模型加的、已经没必要的反复叮嘱
- 同一内容写了很多遍的重复规则
- 和当前规格矛盾的指示
- 已经不用的旧 Skill
- 和其他 Skill、AGENTS.md 冲突的指示

Astra 更能准确遵守指示，所以上面这些旧指示也可能被它认真执行。所以才说「先审计、再整理」。

「Skills 已经不需要了」这个解读，有明确反证。GPT-6 Astra 的 OpenAI 官方模型页，功能列表里现在仍写着「Skills：Supported」。OpenAI 既没有废除 Skills，也没有宣布 Skills 没用了。

Skill 的作用也不只是补模型能力不足。例如：

- 业务特有的步骤
- 公司自己的规则
- 交付物的输出格式
- 多道工序的工作流
- 工具怎么用
- 质量检查标准

这些事，模型再聪明也不会自动知道。把这类信息交给 AI，仍然是 Skill 的工作，以后也需要。

这次 Astra 真正该改的认知，不是「Skill 塞得越多越好」，而是「必要的 Skill，要以没有重复、没有矛盾的状态拿着，这件事变得更重要了」。

如果 Skill 已经是最小构成、职责分得清楚，不必只因为 Astra 出来了就硬删。反过来，多年往上叠规则、Prompt、Skills 的环境，值得做一次盘点。

把 OpenAI 这次的意思准确改写，不是「Skills 的时代结束了」，而是「该按高性能模型，把过时指示和互相打架的 Skill 整理一遍了」。

Astra 让它变得多余的，不是 Skill 本身，而是已经没用的规则、重复指示、给旧模型准备的过度辅助。

参考：OpenAI「GPT-6 Astra Model Guidance」；官方模型页仍写 Skills: Supported；Victor Nunez 的 X 帖。
