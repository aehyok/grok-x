## 推广帖

豆包也出了办公产品。
这下字节终于把 AI 办公这几张牌合在一起了：TRAE、扣子的能力正在逐步往同一个工作入口靠拢，豆包工作又和飞书做了深度打通。
这对国内用户很友好。你不需要梯子，不用折腾海外手机号、信用卡或 API Key，下载安装、扫码登录，就能在自己的电脑上体验一款会读文件、做表格、出 PPT、建飞书多维表格，还能调用浏览器、技能和创作模型的 Agent 产品。
如果你以前只用过普通豆包，先记住两者的区别：普通豆包主要回答问题，豆包工作会继续拆任务、操作文件、调用工具，最后给你一个可以打开的产物。

## 正文

一、下载、安装和注册
1. 从官网下载
打开豆包工作官网，点击「下载豆包工作」。

2. 登录时怎么选
打开客户端后，点击左下角「登录」。当前可以使用豆包或飞书扫码、手机号、飞书账号、抖音账号登录。

如果你只是个人体验，使用豆包账号最省事。公司资料主要放在飞书，就用原本有文档权限的飞书账号，后面接云文档、知识和多维表格会更顺。
登录以后，先把执行模式留在 「按需确认」。它碰到文件、外部服务或关键操作时会停下来让你看一眼，小白阶段更稳。
扫码进入主界面，安装部分就结束了。这里没有命令行，也不用配置开发环境。

二、第一次打开，先认清主界面和九个入口
登录以后，左边会出现新工作任务、定时任务、技能·连接器·伙伴、伙伴对话、云盘、手机遥控电脑、主对话、项目和最近任务。这些入口分别负责：发起任务、自动执行、补充能力、调用固定伙伴、管理飞书资料、从手机接力、保存长期工作和查找历史记录。
第一次使用不需要全部配置。先知道每个入口解决什么问题，等任务真的需要时再点进去。下面按侧边栏从上到下讲。

1. 新工作任务：所有一次性工作都从这里开始
「新工作任务」是你最常用的入口。今天临时要做一份 PPT、整理一个 Excel、读一份合同、总结一篇网页，或者让它打开浏览器查资料，都可以先从这里发起。
它和普通聊天的区别在于：普通聊天通常给你一段文字答案；工作任务会先理解目标，再拆成几个执行步骤，期间可以读取文件、调用技能或连接器，最后生成 Word、Excel、PPT、图片等实际文件。执行过程中涉及账号授权、文件写入或其他重要动作时，客户端会根据确认模式暂停，等你同意后再继续。
你点进去以后，中间会出现一个空白页面，底部有输入框。操作顺序照着下面做：
点击左侧「新工作任务」；
点击输入框左下角的 +，选择一份副本文件；
在输入框里写清楚要它做什么、结果放在哪里；
保留「按需确认」，然后发送；
它开始拆步骤时，先看一眼有没有准备删除、上传或覆盖文件。
比如你手里有一份会议记录，可以直接说：「把这份会议记录整理成结论、负责人、截止时间，另存为新的 Word，不要修改原文件。」任务结束后，这条记录会自动出现在左侧「最近」下面。
看到任务开始列出执行步骤、结束后给出交付文件，并且文件能在指定位置打开，这一步才算跑通。 左侧「最近」只是这次任务的历史入口，并不等于文件已经正确生成。
底部那排按钮也不用背，我给你翻译成人话：
+：把电脑里的文件交给豆包；
工作任务：让它真的动手做，而不是只回答几句话；
项目：告诉它这次工作属于哪个长期项目；
按需确认：碰到重要动作先停下来问你；
企业知识：去已经授权的团队资料里找答案；
更多技能：临时给这次任务加一本工作说明书；
连接器：打开邮箱、网盘、文档等外部服务的入口；
Auto / 高：前面是模型选择，后面是推理强度。这两个设置分别控制“用哪个模型”和“这次任务思考到什么程度”。
2. 模型与推理强度：第一次保持 Auto 就够了
输入框右下角会显示类似「Auto 高」的按钮。点击以后，你会看到 Auto、豆包 2.1 Turbo、豆包 2.1 Pro，以及单独的「推理强度」。模型名称和可选版本可能随客户端更新，先理解它们的分工即可。

Auto：由系统根据任务自动选择模型。第一次使用、普通文档整理、表格清洗和日常问答都建议从这里开始；
豆包 2.1 Turbo：更偏向快速响应。我会把它用于格式转换、摘要、改写和其他目标清楚的短任务；
豆包 2.1 Pro：用于材料多、步骤长、需要综合判断的任务。界面已经标出「额度消耗更快」，没有必要每条任务都开；
推理强度：控制模型在执行前规划和分析的程度。复杂研究、跨文件核对和多步骤交付可以用高强度，简单改格式继续用默认设置。
模型和推理强度是两个独立选项。「Auto 高」表示模型由系统选择，同时使用较高推理强度；它不代表当前固定使用 Pro。高强度也不会自动修正错误，任务完成后仍然要核对文件、数字和来源。
小白可以直接按任务选：改写一段文字、整理一个小表格时用 Auto；材料很多、需要先研究再生成 PPT 时，再尝试 Pro 或提高推理强度。如果结果已经稳定，就不要只为了“更高级”继续增加消耗。
3. 权限模式：决定豆包执行到哪一步必须停下来问你
输入框下方的「始终询问 / 按需确认 / 全部允许」控制工作任务的确认频率。它不会改变模型能力，改变的是豆包在联网和修改文件之前，是否需要先取得你的同意。

始终询问：编辑外部文件和使用互联网时都会询问。第一次处理公司资料、连接新服务或还不熟悉执行流程时，用这个最稳；
按需确认：系统只在判断操作有风险时询问。普通练习和日常办公推荐使用这一档，减少反复点确认，同时保留关键停顿；
全部允许：可以不受限制地访问互联网，并编辑电脑上的文件。它适合已经反复跑通、范围非常明确的任务，不适合作为长期默认设置。
这里还要分清三层权限。任务权限模式负责“执行时要不要问你”；连接器授权决定它能否进入邮箱、网盘等外部服务；macOS 系统权限决定应用能否访问某些本地文件夹、屏幕或麦克风。把任务切到「全部允许」，也不会自动获得一个尚未登录的邮箱账号。
第一次建议保持「按需确认」，并把材料放在单独的练习文件夹里。看到删除、覆盖、批量修改、发送、发布或登录授权时，先读清操作对象和范围再继续；涉及客户、财务和未公开资料时，可以临时切到「始终询问」。
4. 定时任务：让同一项工作按时间自动执行
普通任务每次都要由你点击发送。定时任务会保存任务指令、运行频率和执行时间，到点后自动再跑一遍。它适合内容和步骤比较固定、需要每天或每周重复的工作。

页面里已经准备了工作周报、每日安排简报、新闻推送、竞品动态调研、股价监控和商品价格监控等模板。模板只是预先写好的一份任务框架，点开后仍要检查并补充三项内容：每次具体做什么、在什么时间运行、允许读取哪些资料或调用哪些工具。
例如，你想每天早上收到行业新闻。先在「新工作任务」里手动发一次：「搜索这 3 个网站过去 24 小时的更新，给我标题、两句摘要和原文链接。」确认来源没跑偏、格式也能看懂，再把同一句话放进定时任务，设置工作日早上 9 点运行。
设置完成后，你还要知道结果去哪里看。任务会保留在「定时任务」列表里，你可以检查它是否开启、下一次什么时候运行，也可以查看已经产生的执行记录。暂停一个计划时直接关闭开关，不需要删除整条任务。
定时任务会把错误也一起重复。提示词写错一次，手动任务只错一次；自动任务可能每天错一遍。所以第一条自动化只做查询和提醒，不要让它自动发邮件、删文件、改数据或发布内容。
手动执行一次完全正确，再打开定时开关。
5. 技能：给某一类任务补充固定流程
很多小白看到「技能」，会一头雾水。技能，也就是我们常说的SKill，其实是一组针对某类工作的详细规则，里面可能包含执行步骤、所需材料、输出格式和检查标准。添加技能以后，豆包仍然使用当前任务里的模型，只是做事时会多参考这套规则。
比如「短视频脚本与分镜」技能会要求它考虑镜头、画面、旁白和时长；
「公众号图文」技能会提醒它处理标题、结构、配图和排版。
技能能减少你每次重复说明流程，但你仍然要提供主题、材料、受众和成品要求。

打开「技能 · 连接器 · 伙伴」，点击上方「技能」，再选择分类。新媒体创作里能看到短视频脚本与分镜、公众号图文与运营策略、爆款标题与选题日历、多平台改写分发、去 AI 味和短剧创作。
例如，你只说「帮我写短视频」，豆包需要自己判断时长、画面、台词和节奏；选择「短视频脚本与分镜」技能以后，它会按照更完整的分镜结构处理。此时再补上产品资料、目标人群、视频长度和发布平台，结果通常会更稳定。
使用时有两条路：
在技能市场找到需要的技能，点击卡片右侧的 +；
已经进入任务时，点击输入框下方「更多技能」，临时添加。
点击 + 只是把技能加入可用列表，不会立刻开始执行。回到新工作任务，在输入框下方选择这个技能，再发送具体指令；执行过程里出现「正在加载某某技能」，或者计划开始按照对应流程展开，才说明这次任务已经调用它。
技能不能自动获得外部账号权限，也不会替你补齐不存在的原始材料。一个技能如果需要访问邮箱、网盘或第三方文档，通常还要另外配置连接器。
一个很特别的能力：直接读取这台电脑已有的 Codex Skills
点击输入框下方的「更多技能」，我在这台 Mac 上直接看到了 211 个技能。列表里的 Agently Mail、Lark Approval、Lark Base、Punkadrian Writing、Tutorial SOP 等，正是我原来放在 Codex 和通用 Agent 技能目录里的本地 Skills，并没有先在豆包工作里逐个上传。

我又检查了客户端当天的本地日志。豆包工作会读取 .agents/skills，也会检查 .codex/skills，同名技能还会做去重。所以这里更准确的说法是自动发现和聚合本机 Skills：打开「更多技能」就能选择，省掉重新安装一遍的步骤。
不过，“列表里能看见”和“换个 Agent 也能完整执行”是两件事。只包含写作规则、步骤和模板的 Skill，通常更容易跨产品使用；依赖 Codex 专属工具、MCP、环境变量、命令或固定路径的 Skill，换到豆包工作后仍要实际跑一次。我的日志里就有一个 Skill 因 YAML 格式解析失败而没有正常加载。
你可以先选一个低风险的文字类 Skill，发一条小任务，观察执行计划里是否显示已经加载该 Skill。确认规则生效、没有缺少工具，再去测试需要发邮件、修改云文档或运行脚本的复杂 Skill。
6. 连接器：让豆包访问外部服务
你的 QQ 邮箱、腾讯文档、百度网盘、Notion、GitHub 都属于外部服务。豆包默认看不到这些账号里的内容，必须通过连接器完成登录和授权，之后才能在允许的范围内搜索、读取、创建或修改内容。
每个连接器提供的动作并不相同。例如邮箱连接器可能支持搜索邮件、读取附件和发送回复；会议连接器可能支持查询会议和创建预约；网盘连接器通常负责搜索、上传和下载文件。具体能做什么，要以授权页和连接器说明为准。

实测页面里能看到企业微信、钉钉、巨量引擎、QQ 邮箱、腾讯会议、腾讯文档、金山文档、Notion、百度网盘、GitHub、Wind、同花顺、天眼查和企查查等入口。分类横跨办公、金融、法律、内容、电商、出行和开发。
连接器页面按金融、法律、新媒体创作、办公协作、电商营销等类别整理。你可以直接搜索服务名称，也可以从分类里找。
连接一个服务时，按这个顺序检查：
先确认它是不是当前任务真的需要；
点击连接器右侧的 +；
阅读授权页，看它要读取、创建、修改还是发送什么；
第一次优先选择只读或最小范围；
回到任务里，明确写出允许它做的动作。
例如，你只想整理 QQ 邮箱里的会议通知，就写：「只搜索最近 7 天标题包含‘会议’的邮件，整理时间和参会链接，不回复、不转发、不删除。」看到它返回了邮件标题和日期，同时邮箱里没有新增发送记录，就说明这条连接器用对了。
如果任务提示「没有权限」「未找到账号」或「需要登录」，先回到连接器页面检查授权状态，不要反复改提示词。授权成功只代表豆包具备访问通道，每一次实际读取和写入仍然受账号本身的权限限制。
三个概念的区别可以直接记成：技能规定处理方法，连接器提供外部数据和操作入口，伙伴保存角色与长期分工。
7. 工作伙伴：保存一套可以反复使用的专业角色
普通任务主要围绕当前指令工作。工作伙伴则提前配置了岗位名称、擅长内容、常用技能和处理方式，适合把一类重复工作长期交给同一个角色。你每次仍然要提供这次任务的材料和目标，但不用从头解释它应该扮演什么岗位。

伙伴市场里有数据分析师、PPT 制作专家、UI 设计师、高级开发工程师、AI 画师、短视频脚本编剧、HR 招聘助手、战略报告顾问等角色。每张卡片下面都会写它擅长什么，你先看岗位，再看描述，最后点右侧的 + 或「召唤」。
什么时候值得用伙伴？看任务会不会重复：
临时整理一张表：开「新工作任务」更省事；
每周都要做经营复盘：固定找数据分析师；
每个月都要向老板汇报：固定找 PPT 制作专家；
长期经营一个内容账号：固定找内容创作伙伴。
点击卡片可以先看角色说明，确认它的能力和你的任务匹配，再点 + 或「召唤」。召唤成功后，这个角色会出现在「伙伴对话」里；以后可以直接从那里发起任务，不用重新翻伙伴市场。
8. 伙伴对话：管理已添加的伙伴、小队和任务模板
「工作伙伴」页面用于查找和添加角色，「伙伴对话」页面则集中显示已经添加的伙伴、默认工作伙伴小队，以及系统准备的任务模板。它解决的是“下次从哪里继续找这个角色”的问题。

页面上半部分是伙伴和小队卡片。点击单个伙伴，会进入与这个专业角色的任务页面；点击小队，会进入包含多个角色的协作入口，由系统根据任务安排不同角色参与。页面下方的「发起任务」是预设示例，你不知道第一句话怎么写时，可以先点一条，再替换主题、材料和输出要求。
第一次使用可以这样走：
去伙伴市场召唤一位「PPT 制作专家」；
回到左侧「伙伴对话」；
点击这位伙伴的卡片；
上传一份脱敏材料；
只让它先给页纲，不要直接生成最终稿；
页纲方向正确，再继续做 PPT。
伙伴对话的价值主要有两点：
第一，同一角色可以连续处理相关任务，工作入口不会散落在大量普通对话里；第二，小队可以把研究、写作、设计等环节放在一次协作中完成。你仍然需要检查每一步产出，小队成员多并不代表结果一定正确。
豆包工作和飞书工作伙伴体系有联动，但当前能看到谁，取决于登录账号、所在工作空间、管理员配置和已有权限。
我发现，我登录的飞书，工作伙伴里出现了我的飞书Bot，但飞书里的所有 Bot 不会保证自动出现在这里。 页面里出现了你刚召唤的伙伴，或者默认小队能正常打开对话，说明当前账号已经可以使用这部分能力。
一个人的任务用伙伴，明确需要研究、设计、写作等多角色配合时再用小队。小任务硬上小队，会多出分工和沟通过程，反而更慢。
9. 云盘：直接查看和使用飞书云文档
点击「云盘」以后，你看到的是与当前账号关联的飞书云文档入口。这里不是新建了一套独立存储空间；你在飞书里有权限查看的文档、电子表格和多维表格，会按照「最近、我的、共享、收藏」等分类显示。

你可以在这里新建、上传、搜索和打开资料。豆包执行任务时，也能在授权范围里读取这些资料；如果任务要求创建文档、更新表格或写入多维表格，结果还可以直接保存回飞书。所谓“和飞书同步”，指的是两边访问同一份云端文件，并不需要先下载到电脑再重新上传。原来的评论、共享和访问权限仍然由飞书管理。
第一次打开云盘，先做三个检查：
看右上角登录的是不是你准备使用的飞书账号；
点击「我的」，确认能看到自己熟悉的文档；
搜索一份没有敏感信息的测试文档。
接着开一条普通任务，说：「读取云盘中的【文档标题】，只总结主要内容，不新建、不修改、不分享。」返回的标题和内容都对，说明读取链路已经跑通。之后再尝试新建文档或写入多维表格。
如果云盘里找不到某份文件，先检查飞书账号和原文档权限。文件在飞书里对你不可见，豆包也不会绕过权限把它找出来。
10. 手机遥控电脑：离开电脑后继续查看和控制任务
这个功能用于在手机上接续电脑端的工作任务。电脑仍然负责运行任务和访问本地文件，手机端主要用来查看进度、接收提醒、补充指令或继续操作。它不会自动把电脑中的全部文件复制到手机，也不是完整的远程桌面。

使用前需要满足三个条件：手机和电脑登录同一账号、电脑在线、电脑端打开「可被相同账号的设备控制」。长任务还可以打开「让这台设备保持唤醒状态」，避免电脑睡眠以后任务停住。
操作时，先在电脑上开始一个低风险任务，再打开手机豆包，进入工作任务并选择这台电脑。手机能看到同一条任务的进度，并能继续发一句补充要求，就说明设备已经连接。电脑离线、进入睡眠或退出豆包工作以后，手机端通常无法继续推进本地任务。
用完立即关闭远程控制和持续唤醒。公共电脑、公司共用电脑，以及存放客户资料、财务资料的电脑，不要长期打开这个开关。
11. 项目：集中管理长期任务和本地资料
普通任务主要保存当前这一条任务记录。项目用于集中管理同一个长期主题下的任务，并绑定需要使用的本地文件夹。比如「客户 A」「公众号运营」「Q3 产品发布」都可以各自建立项目，让相关任务和资料保持在同一个范围内。

创建时需要填写项目名称并选择本地文件夹。项目名称尽量写清对象和目标；
本地文件夹只选择这项工作需要的目录，不要为了省事把整个桌面、下载文件夹或整块云盘都交进去。豆包在项目中能接触哪些本地材料，首先取决于你选择了哪个文件夹。
什么时候需要项目？
同一批资料已经用到第三次，或者这件事会连续做几周，就可以创建项目。只有一份临时表格，继续使用新工作任务即可。
创建成功后，左侧「项目」下面会出现项目名称。进入项目再开任务，豆包应该能看到你添加的文件夹；它看不到时，先检查项目是否选对、文件是否真的位于那个文件夹，不要急着扩大权限。

三、小白第一次开工：先跑 PPT、Excel 和定时任务
第一次不要同时交付一堆文件。先选一份脱敏材料，让豆包只完成一种结果；你能打开、能检查，再做下一种。
动手前，在电脑上新建一个练习文件夹，里面再建两个小文件夹：input 放材料副本，output 放豆包生成的结果。原文件继续留在原来的地方，这样即使第一次操作出错，你也不会丢东西。
接下来所有练习都走同一条路：
点击「新工作任务」；
点击输入框左下角 +；
从 input 里选择材料；
粘贴提示词并替换【方括号】里的内容；
发送后先看执行计划；
完成后去 output 打开结果。
它如果准备写到其他文件夹，或者准备上传、发送、覆盖原文件，先不要点确认。把保存位置和禁止动作再说一遍。
一条能执行的任务，至少写清四件事：材料、任务、约束、验收。
1. 让它做一份 PPT
最稳的办法是分两次：先让它写页纲，你看完再让它生成文件。页纲就像作文提纲，方向错了时改八行文字很容易；等 8 页 PPT 全做完再改，时间会浪费很多。
2. 让它整理 Excel
Excel 最容易出问题的地方是：豆包为了把表格整理漂亮，顺手改了原始数据。第一条要求永远写「保留原始数据页」，这样你还能回头核对。
先看原始行数是否和输入文件一致，再看汇总金额，最后点开两张图表确认标题和横纵轴正常。
遇到姓名相同、日期缺失、金额格式混乱等情况，豆包可能问你该怎么处理。看不懂时让它「先把无法判断的行放进异常清单，不要删除」，这样最安全。
3. 让它做一条定时任务
定时任务先不碰自动发送。你只做一条每天查资料、把结果留在豆包里的任务，就足够理解整个功能。
返回结果以后，点开其中两条链接，确认网页能打开，标题和摘要也能对上。然后去左侧「定时任务」，点击「新建」，粘贴同一段指令，把运行时间设为工作日早上 9 点。
保存前再看一遍：重复频率是不是工作日、时间是不是上午 9 点、任务说明里有没有「不发送、不发布、不修改」。三项都对，再保存。自动化阶段只新增时间和通知方式，不要顺手扩大权限。
4. 还有哪些日常工作可以直接交给它
会议整理：把录音或纪要变成结论、负责人、截止时间；
文件整理：把一批 Word、PDF 或图片按规则重命名并归档；
资料研究：读取公开网页，做一份每条判断都带链接的竞品简报；
内容写作：根据产品资料写报告、邮件初稿、公众号文章和短视频脚本；
飞书协作：读取飞书文档，再新建文档、电子表格或多维表格；
图片视频：根据已经确认的文字生成海报、封面和视频草案。
你可以把任何工作先缩小成一个动作。例如「帮我运营公众号」太大，先改成「读取这份产品说明，给我 10 个选题，只输出标题和一句理由」。第一步能验收，再让它写正文、配图和排期。
看到完成提示后，至少检查三件事：文件能打开、结构符合要求、关键数字或事实能回到原材料。需要返工时让它保存 v2，不要覆盖第一版。

四、豆包工作最有辨识度的两条生态链
1. 飞书生态：资料处理完，结果还能回去
豆包工作的团队页面明确写了飞书账号登录、连接飞书数据源、读取用户有权限的内容，以及把结果写回飞书继续评论和编辑。团队还可以共享 Skill，让同一套流程在成员之间复用。
“读”是让豆包在账号权限范围内查找飞书文档、电子表格、多维表格或团队知识；
“写回”是把整理后的结果直接新建或更新到飞书中。
文件仍然留在飞书，团队成员可以沿用原来的评论、分享和协作方式，不必先把文件下载到电脑、处理完再上传一次。
对于平时把会议纪要、项目资料、销售数据和知识库都放在飞书里的团队，这一点会明显减少文件搬运。
你可以让它读取一份会议纪要，再创建待办清单；读取一张销售表，再把汇总结果写进新的多维表格；或者查找几份团队文档，整理成一份可继续协作的报告。
这里我也测试了，直接用豆包工作创建了一张飞书多维表格：

它执行的过程可以拆成五步：先在飞书中新建一个 Base；把本地 CSV 的 9 行销售数据导进去；新增名为“季度”的一列；给 9 行数据统一填入 Q1；最后创建一个按“产品”分组的视图。完成后它又重新读取整张表，核对行数、字段和分组设置，避免只创建了空表就宣布完成。

你在自己的账号里照做时，至少验收四件事：飞书里是否真的出现新表、9 行数据是否都在、季度列是否全部为 Q1、分组视图是否能按产品展开。任务页面写着“完成”只能作为提示，打开最终表格检查才算验收。
如果你的公司资料本来就在飞书，这条链路会很顺：
飞书文档、表格、Base、知识 → 豆包工作读取和处理 → 结果回到飞书协作。

2. 豆包生态：Office 做完，继续生成图和视频
豆包工作的另一条特点来自字节自己的 AI 产品和模型能力。TRAE 主要面向编程和软件开发；扣子长期积累了 Agent、Skill、工作流和连接器；豆包模型负责文字理解、分析和内容生成；Seedream、Seedance 则分别面向图片和视频创作。豆包工作正在把这些能力放进同一个桌面任务入口。
官方页面列出了 Seedream 5.0 Pro 和 Seedance 2.5，技能市场里还能看到公众号、营销素材、短视频、设计、电商和编程任务。

我继续让它做一张教程海报。图片任务比纯文字多了几个必须说明的条件：画面比例决定横图还是竖图，主标题和副标题要逐字写清，人物、配色和使用场景也要交代，最后还要指定 PNG 或 JPG 等文件格式。

它调用创意设计能力，生成了一张 2048×1152 的图片。任务完成后我检查了三项：图片能否打开、画面比例是否接近 16:9、主副标题是否准确。执行时还发现原文件虽然使用 .png 后缀，实际编码是 JPEG，于是又把它转换成真正的 PNG。

这条工作流很适合内容团队。同一份研究材料可以先整理成文章或报告，再提炼成 PPT，之后继续生成封面、社媒卡片和视频草案。任务之间可以沿用已经确认的标题、事实和视觉要求，减少在多个产品之间反复复制材料。
本次只实测了图片生成，没有实测 Seedance 视频。模型版本、账号权限和开放范围会变化，你需要以自己的客户端为准。
3. 定时任务和手机遥控，最后再开
定时任务和手机遥控都属于“让任务离开当前这次点击后继续运行”的能力，所以放在熟悉普通任务以后再设置。定时任务适合周报、每日简报、新闻和竞品监控；手机遥控适合电脑正在执行长任务、本人暂时离开电脑的情况。
我填写了一条一次性「教程验收提醒」，明确要求只发送提醒，不读文件、不联网、不修改内容。配置页里最重要的是频率、时间、任务指令和权限边界：频率决定执行一次还是重复运行，时间决定何时触发，任务指令决定每次具体做什么，权限边界决定它能否读取或改动外部内容。

这次演示只完成配置页，没有保留定时计划。真正使用时，先手动跑通，再从低频、只读任务开始；涉及发送、修改和发布的流程继续保留人工确认。
手机遥控同样放到最后。需要出门继续电脑任务时再开，使用结束后关闭设备控制和持续唤醒。

五、已经用过 WorkBuddy 或 Codex，豆包工作怎么选
豆包工作和 WorkBuddy
WorkBuddy 更像一间已经摆满工具的办公室。它的客户端有日常办公、代码开发和设计创意，项目里还能放资产库、指令、个人记忆、专家、技能、连接器和自动化。
这些名词和豆包工作有相似之处：WorkBuddy 的“专家”接近豆包的“伙伴”，都是预先设定好的专业角色；“连接器”都负责接入外部服务；“项目”都用于保存长期任务和资料。区别主要在生态入口和产品组织方式，不在于谁能不能写一段文案。

我实测的 WorkBuddy 5.3.13 连接器页面显示 129 项，并支持自定义连接器。QQ 邮箱、ima、腾讯乐享、腾讯文档、腾讯会议、企业微信等腾讯系入口排得很靠前。

Skills 这一项，我重新查了 WorkBuddy 官方手册和本机客户端。官方手册写得很清楚：WorkBuddy 支持上传本地技能包，导入后会自动完成配置；已经安装的本地技能可以直接在对话中调用。因此，“Codex Skill 到 WorkBuddy 全部都要重新适配”这个说法太绝对。
两边的实际差异在导入方式。当前这版豆包工作会自动发现 .agents/skills 和 .codex/skills，我打开「更多技能」就看到了原有列表；WorkBuddy 默认管理自己的用户技能和项目技能，需要先把本地 Skill 上传或放进它的技能目录。完成导入后，标准 SKILL.md 结构的技能有机会直接使用。
需要适配的通常是运行环境，不是那份说明文字本身。一个 Skill 如果只保存写作规则、检查清单和提示词，迁移相对容易；如果写死了 Codex 工具名称、MCP、插件、命令路径或授权方式，到了豆包工作和 WorkBuddy 都可能缺少依赖。豆包在“发现已有 Skill”这一步更省事，WorkBuddy 也支持本地 Skill，但要先导入；两边都不能保证所有 Codex Skill 原样执行。
WorkBuddy 的项目、任务交接、记忆和权限说明更完整。官方手册会单独解释默认权限、Full Access、工作空间、受保护路径、删除确认、脚本和网络能力，适合愿意认真搭建长期工作区的人。
豆包工作的主页更集中，第一次上手需要理解的东西更少。它的优势集中在飞书原生协作和豆包创作模型：资料已经放在飞书时，可以从云盘读取，再把文档、表格或 Base 结果写回去；内容处理完以后，还能继续调用字节系的图片和视频能力。
最简单的选择方法，是看你每天打开电脑后先进入哪个系统。工作从飞书文档、飞书表格、飞书知识库开始，豆包工作的路径更短；工作从企业微信、腾讯会议、QQ 邮箱、腾讯文档和其他业务系统开始，WorkBuddy 的连接器覆盖更值得优先测试。
豆包工作和 Codex
Codex 的主场是本地项目与代码库。OpenAI 官方文档里，它可以挂载多个文件夹、读取和修改文件、运行终端命令，还能查看 diff、逐块暂存或还原、提交与推送 Git、创建 PR，并通过 worktree 并行处理代码任务。
这里的差别来自工作对象。Codex 会把代码文件、终端命令、Git 变更和自动化测试当作主要工作材料，因此适合开发软件、排查程序错误和维护代码仓库。它也能处理普通文档，但操作界面和验收方式明显偏向工程工作。
豆包工作面对的主要是 Word、PPT、Excel、网页资料、飞书文档和多维表格。普通办公用户不需要先理解终端、分支或代码差异，就能用中文描述任务，并从交付卡片里打开结果。如果你每天面对代码仓库、终端、Git、测试和 PR，Codex 更专业；日常工作主要是文档、表格、中文研究和内容创作，豆包工作的界面与生态更贴近这些动作。

直接按主战场选
不要只比较“谁的模型更聪明”。先列出你一周里最常处理的资料放在哪里、最后要交付什么，再按下面三条判断：
资料都在飞书，还经常做 Word、PPT、Base、图片和视频：选豆包工作。
资料散在腾讯文档、ima、企业微信、QQ 邮箱、腾讯会议和多个业务系统：优先看 WorkBuddy。
每天面对代码库、终端、Git、测试和 PR：选 Codex。
也可以让三款产品各做自己擅长的部分：豆包负责飞书资料和办公成品，WorkBuddy 处理腾讯生态与多连接器流程，Codex 负责代码和工程自动化。

六、小白最适合的升级路线
不要第一天就把云盘、连接器、定时和远程全部打开。按下面五级升级，哪里出错都容易找：
粘贴一段脱敏文字，只让它整理；
读取一个副本文件，输出一个新文件；
单独跑通一份 Excel 或 PPT，并按原材料验收；
连接飞书，先读取，再创建一个仅自己可见的多维表格；
单次任务稳定后，再加项目、伙伴、定时和手机接力。
你今天只需要完成前两级。
新建一个练习文件夹，放入一份没有敏感信息的材料，然后发出第一条任务：

豆包工作的门槛已经压得很低：国内网络、国内账号、中文界面，装完就能开始。
剩下的习惯只有一句话：
先让豆包干，再由人验收。
