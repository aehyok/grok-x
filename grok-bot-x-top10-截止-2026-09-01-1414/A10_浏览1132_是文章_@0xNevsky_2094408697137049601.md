## 正文

我进去是想给自托管栈辩护。出来承认 Grok Bot 赢了。

同一份活——三人 Agent 团队发 X——在 Grok Bot、Buzz、OpenClaw、Hermes 上各跑一周。同一任务、同一内容目标、四个引擎。想知道普通人到底该伸手拿哪个。并不接近。不是因为 Grok 更聪明——模型不是故事。它赢在决定 Agent 团队碰到真活后能不能活下来的三件事：安装、在线、交接。另外三个在哪输，文里会摊开。结尾会直说 Grok 的真实取舍。但在「它是否真的在你不在时跑你的活」这个指标上，它赢了我这一周。

### 第 1 部分：Agent 团队到底是什么

打开 Grok Bot 像什么都没有：消息窗、侧边名字、聊天线程。第一天像任何聊天 App。但每个名字不是线程，是有岗位、跨任务记忆、以及——这才重要——自己电脑的队友。浏览器、文件系统、终端跑在数据中心，不在你桌面。任务做到一半合上笔记本，活还在继续。从来没绑在你的机器上。一个账号、一台共享云电脑、每个 Agent 自己的屏幕。文件、登录、浏览器会话都在那台共享机器上，一个存的下一个立刻能用。不用导出，不用手动交接。Agent 不再是你在终端里一行行盯的东西，开始像一支碰巧跑在云上的小型远程团队。

### 第 2 部分：四种路径，说白

- **Grok Bot**：就是能用。当队友不当工具。每个 Agent 自己的云电脑，登录真实界面，Agent 互相说话。你的活缩成盯审批队列，而不是基础设施。代价：零控制，后面会说。
- **Buzz**：共享房间。本身不是 Agent，是你把 Agent 丢进去的环境。自托管或连公共中继。一周前作者觉得 Buzz 已经是创建 Agent 最快的。然后 Grok Bot 让它显得容易。
- **OpenClaw**：老兵。本地优先编排器，有自己的 skill 系统和控制面。自托管或一键 VPS。基础设施是你的问题。
- **Hermes**：脑子。会从自己的运行里拉新 skill 的自改进运行时。和 OpenClaw 一样，你来托管。

煮下来：OpenClaw 和 Hermes 控制最多，但配置开销真——模型、SOP、维护。Buzz 在中间——跑起来顺，但初始私钥步骤能吓退非技术用户。Grok Bot 无摩擦——假设你已经付对的订阅。

### 第 3 部分：为什么 Grok Bot 赢了这一周

三个测试，不是榜，是发帖时撞到的真摩擦。

1. **到第一个能干活 Agent 的时间。** Grok Bot：分钟级。绑在订阅里，没有要立起来的基础设施。OpenClaw 要先备 VPS、接线模型，Agent 才存在。Hermes 还要 SOP 脚手架。Buzz 快，但私钥步骤对非技术是真墙。安装上 Grok 不是领先一点，是不同重量级。
2. **走开时的在线。** 这个才真正要紧。每个 Grok Agent 跑在自己的云电脑上，合上笔记本研究 Agent 通宵扫完源，早上草稿已就位。自托管 OpenClaw 和 Hermes 的「永远在线」只和你付钱养活的那台盒子一样可靠；VPS 打嗝，运行一起死。Grok 的活从不绑你的机器，没什么要盯。
3. **Agent 之间的交接。** 团队的意义是一个的输出变成下一个的输入。Grok Bot 上研究→创意→草稿自动过，因为共享一台机器和一份记忆。在 OpenClaw 和 Hermes 上重现意味着自己接线交接。Buzz 共享空间不错，但管中继花的时间仍比 Grok 多。

加起来：起来最快、唯一真正你走了还在跑、交接最干净。专门跑 X 内容，另外三个至少在一根轴上输，Grok 三根全赢。

### 第 4 部分：诚实成本

进 Grok Bot 三条路：Super Grok Heavy 300 美元/月；Cursor Ultra 200 美元/月；Cursor Teams Premium 120 美元/座。都含每周用量池，超出按模型和 token 计。另外三个「免费」带星号：OpenClaw/Hermes 软件免费，但要自己的硬件跑本地模型，或付 API，或接已有订阅。Buzz 开源，同样逻辑。Buzz 接到 Claude Code 订阅比 OpenClaw/Hermes 干净。Grok Bot 跳过这一切——绑进你已经在付的档。这就是整套 pitch。

### 第 5 部分：取舍（那一刀）

方便总有价。Grok Bot 出现在三处：你选不了模型，就是 Grok；你不拥有 harness，它绑在订阅里；数据在他们的云电脑上，不在你的。不是自动的交易破坏者，但是真交易：速度和方便换控制。一直自托管优先的人，all-in 前先坐一会儿。一个摩擦：设置在还没签它跑的那档之前就要信用卡。没和已有付费 X 订阅同步。底层是 Cursor 产品套 Grok 标签，从用户座位上看，多出来那步没必要。

### 第 6 部分：跑过的 3 Agent X 系统

因为每个 Agent 有带浏览器和文件系统的持久电脑，它真的擅长通常一自动化就散架的 X 工作流：研究、起草、创意并行，互相喂，不用手动复制。

- 研究 Agent：盯趋势、挖仓库和公开讨论，捞真值得写的，而不是猜日历。
- 创意 Agent：喂几张喜欢风格的参考信息图，之后生成匹配审美的视觉，而不是从空白画布开始。
- 起草 Agent：把研究和创意方向变成帖子文案，暂存待审。

共享电脑和记忆，所以一份完成的研究下一份立刻能用。起草 Agent 从不等我粘贴。

两条苦学：把 Agent 放进共享团队聊天，它们会一起丢掉保存例程的能力。例程就是更好听的 cron，必须在每个 Agent 的单独会话里设日程。小 UX 缺口，建整队前值得知道。你可以录自己做一次重复任务来教 Agent：开始录、做任务、停。对发帖工作流里乏味可重复的部分真有用。上面再放一个通才 Agent 给你每日汇总，差别是知道 Agent 完成了什么，还是希望它们做了点什么。

这套配置不断收敛到的内容建议——多数人知道却很少坚持：发真的、有用的或有趣的，最好三者都有。一帖一个想法。回比广播多。视频和图片打纯文字，但真正风险不是算法，是无聊。别赌系统，规则每月都变。唯一常量是有真实要说的，并且持续说，听起来不像品牌号。

### 第 7 部分：人们实际在建什么

有意思的不是演示功能，是人们把 Agent 团队越来越不当聊天机器人、当小公司。模式：点三四个 Bot 的名，各给具体活，像同事一样发消息。有人五到十分钟从现有 Instagram 当参考立起「品牌团队」——内容、助理、品牌合作——输出已经像做它的那个人。真正有意思的是交接：助理 Bot 被要求去签 NDA，交给品牌合作 Bot，没有人管中继。Bot 到 Bot 通信是这个品类要去的地方。野外快照：参谋长 Agent 研究你的公开活动和当前 Bot 花名册再建议怎么重组；SEO/内容 Bot；公关 Bot；付费广告 Bot；外联约见面 Bot（作者觉得会变成最常见用例）；以及订机票、按食谱照片买菜、修几百张扫描的 GPS、谈承包商报价、会前翻译销售 deck。最后这批说明：这不再只是开发者工具。

### 落地

我走进去是自托管纯粹主义者。原始控制和数据所有权，OpenClaw 和 Hermes 仍赢那个具体论点，Buzz 是你在 Claude Code 上时最干净的中间路。但我实际在测的问题不是「哪个控制最多」，是「哪个在我不在时跑我的活」。那个问题上 Grok Bot 赢得很清楚——起来更快、唯一真正我走了还在跑、唯一交接就发生了。专门做 X 内容，这周没有别的接近。

把那一刀说白，免得像广告：你用控制付这笔赢。模型只能是 Grok，你不拥有 harness，数据在他们云上不在你的。这三件是交易破坏者，自托管仍是你的道，那是合法选择。对其他人——只想下周有内容团队在跑、不想变成系统管理员——Grok Bot 是我现在会递出去的那个。

底下不舒服的真话：工具不再是难的部分。在 Grok 上立三人团队要分钟。仍然自动化不了的，是有真实要说的东西。Agent 研究、起草、排期——它们不能让你值得被关注。赢家十分钟跑起你的活。值得被读仍然要你。
