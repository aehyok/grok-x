## 正文

作者大量用 Grok Bot 后发现：很多用量是无意识浪费。下面这些改法让他在限额内做完更多事。

1. **能用事件触发就别轮询。** 不要每隔几分钟叫醒 Bot 去检查。让 Slack、GitHub、reaction 这类真事件触发，有事才跑。
2. **写明卡住就求助。** 加一句：「If you're stuck or can't make progress, just let me know.」避免同一失败步骤空转烧 token。
3. **优先用 connector，少用浏览器。** 浏览器意味着大量点击、截图、额外步骤。connector 通常更快更便宜。
4. **Skill 写短、只干一件事。** 巨型 skill 什么都想做。信息太少会乱跑，太多会晕。
5. **别把编码塞进 Bot 聊天。** 改仓库交给编码 Agent / Cursor / CLI。Bot 只协调。
6. **一次性 watch 用完就删。** 否则后台一直跑，悄悄吃限额。
7. **别把 routine 定太勤。** 每 15 分钟跑一次，一天能接近 100 次。问自己是否真需要。小时级或一天几次通常够。
8. **小心超长聊天。** 长对话会让周期性 routine 更贵，因为每次都要处理全部历史。重复任务用新 Bot，别用主对话。
9. **Bot 描述里写清 skill 路径。** 例如 “Skills are in /skills folder.” 省得它到处找。
10. **能用小脚本就别上完整 skill。** 定期查 API 用小脚本更干净更便宜。别打太勤。
11. **定期审计 routine。** 有的还在跑，你已经不需要了。
12. **重要上下文放进文件。** 别把指令和知识只堆在一条长聊天。放进 .md，新 Bot 能直接捡。
13. **别让一个 Agent 干所有事。** 日常一个主助手；研究、编码、监控分给专职 Bot。
14. **Agent 可丢弃，上下文要永久。** 重要东西在文件里，随时可以拉起新 Agent。
15. **重复活别放在主助手上。** 主对话不要又长又贵。

额外：别为了省 token 把指令写得太短。多几行清楚的话，往往能避免迷路、重试、走错路，反而更省。

也可以把整份清单丢给 Bot，让它审查你现有的 routine、skill 和日程。

TLDR：有真事才叫醒；脚本和 connector 更好就用；skill 聚焦；重要东西放文件；不同活给不同 Agent。

## 原文

Been using Grok bots a lot lately and noticed something simple: most of the time we waste usage without realizing it.
Here are the practical things that actually helped me get way more done while staying under limits. Sharing in case they help you too.
1. Use event triggers whenever you can: Don’t make the bot wake up every few minutes just to check. Let something real trigger it — a Slack message, a GitHub update, a reaction. It only runs when something actually happens.
2. Tell the bot when to ask for help: Add this line: “If you’re stuck or can’t make progress, just let me know.” Stops it from looping the same failed attempt over and over while you watch tokens disappear.
3. Prefer connectors over the browser: If a connector can pull the info you need, use it. Browser automation means lots of clicks, screenshots, and extra steps. Connectors are usually faster and cheaper.
4. Keep skills short and focused: Don’t write a giant skill that tries to do everything. Give it only what it needs for that one job. Too little info and it wanders. Too much and it gets confused.
5. Don’t force coding into the bot chat: If you need to change code in a repo, let a coding agent (or Cursor / CLI) handle it directly. Your bot can just coordinate instead of doing all the coding itself.
6. Delete one-time watches when you’re done: Created a temporary watch? Remove it the moment you no longer need it. Otherwise it keeps running in the background and quietly uses your limits.
7. Don’t schedule routines too often: A routine that runs every 15 minutes can hit almost 100 times a day. Ask yourself if you really need that frequency. Hourly or a few times a day is often enough.
8. Be careful with very long chats: Long conversations make recurring routines more expensive because the bot has to process all that history. For repeating tasks, start a fresh bot instead of using your big main conversation every time.
9. Put the skill path in the bot description: If your skills live in a repo or folder, tell the bot exactly where. Example: “Skills are in /skills folder.” Saves it from searching around.
10. Use simple scripts when possible: Not everything needs a full skill. If you’re just checking an API regularly, a small script is often cleaner and cheaper. Just don’t hit the API too frequently.
11. Regularly check your routines: Sometimes routines get created and you forget how often they run. Take a quick look every now and then — you might find something still using limits that you no longer need.
12. Store important context in files: Don’t keep all your instructions and knowledge only inside one long chat. Put the useful stuff in .md files. Then any new bot can pick them up easily.
13. Don’t make one agent do everything: Have one main assistant for your day-to-day work. Create separate bots for specific jobs — research, coding, monitoring, etc.
14. Make agents disposable, keep context permanent: Agents can come and go. Your knowledge shouldn’t. As long as the important stuff lives in files, you can spin up a new agent anytime and give it those files.
15. Keep recurring work off your main assistant: Let your main bot stay focused on what you’re actively working on. Hand the repetitive stuff to separate bots so your main conversation doesn’t grow huge and expensive.
Bonus tip: Don’t try to save tokens by making instructions too short. A few clear extra lines can actually save tokens by stopping the bot from getting confused, retrying, or going down the wrong path.
You can even give your bot this whole list and ask it to review your current routines, skills, and schedules. It will often spot waste you missed.
TLDR: The simple idea to follow
- Only wake bots when something real happens.
- Use scripts and connectors when they’re better.
- Keep skills focused.
- Store the important stuff in files.
- And use different agents for different jobs.
That’s it. Small changes, but they add up really fast and you end up saving a lot of $ in the long run.
