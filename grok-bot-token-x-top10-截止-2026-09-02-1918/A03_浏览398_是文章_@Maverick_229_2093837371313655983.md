## 正文

作者想节省 Grok Bot token，做成「一个 Slack 项目频道 + 标签选工人」的配方。核心不是让 Bot 自己干活，而是让 tag 决定谁消耗哪一池额度。

先分清三个产品，不要混：

- **Grok Bot**：有自己云电脑的桌面/iPhone 应用。在 Plugins 里连 Slack，协调者才能盯频道并回帖。
- **Grok for Slack**：另一个 Slack 应用，频道里是 @Grok。装它不等于装了 Grok Bot。
- **Cursor Slack 应用**：频道里是 @Cursor，活归 Cursor，不归 Grok Bot。

设计就一句话：**标签选工人。** 监听器/插件让协调者看同一频道。

搭完后：手机在频道发一条，Cursor 能开 PR；合并后可跑本地测试；结果回到同一条 thread。

作者的 token 口径（文末）：Grok Bot 的 token 停在协调层；Cursor、Hermes、ChatGPT 各自在自己的上下文里干活。

工作规则（钉在频道）：

1. 新活开新 thread
2. 点名工人：@Cursor = 编码；Hermes = 本地测试；ChatGPT = 审查
3. Grok Bot / Chief of Staff 只看，不抢 tag
4. Cursor 完成 = 开 PR
5. 代码完成的检查点 = 已合并 PR
6. 测试默认在合并后跑
7. 结果回同一 thread
8. 写明谁跑的、下一位 owner 是谁
9. Bot 状态帖不是新任务

协调者只允许：发现新请求、认出被 tag 的工人、盯 thread、工人超时才说话、合并后再做终测、回结果并 tag 下一位。不允许：Cursor 当 owner 时改补丁、把每条 bot 消息当新请求、同一 thread 再拉第二个 agent、打印密钥。

两个协调者盯同一频道必须有一个闭嘴，否则会死循环。

完整逐步安装（Slack 工作区、频道、GitHub、Cursor Slack、Grok Bot 插件、可选 ChatGPT/Hermes、手机端全链路测试、故障排查）见原文。

## 原文

This is a setup guide. It starts with no Slack account. It ends with one project channel that can send work to the right bot and bring a result back.

Read this first. There are two different Grok products. Do not mix them up.

Grok Bot is the desktop and iPhone app with its own cloud computer. You connect Slack to it under Plugins. That connection is how a coordinator can watch a channel and post back.

Grok for Slack is a separate Slack app. In a channel it answers as @Grok. Installing that app does not install Grok Bot.

Cursor has its own Slack app. In a channel it answers as @Cursor. That tag goes to Cursor, not to Grok Bot.

That split is the whole design. The tag selects the worker. The listener or plugin lets the coordinator watch the same channel.

What you are building

You will have:

1. A Slack workspace.
2. One project channel.
3. The Cursor Slack app in that channel.
4. Grok Bot connected to the same workspace, with a named coordinator Bot.
5. GitHub connected so Cursor can open a pull request.
6. Optional: ChatGPT in Slack for review.
7. Optional: Hermes in Slack for local files and live tests.

A phone message in the channel can then start work. Cursor can open a pull request. After merge, a local test can run. The result can return to the same thread.

Grok Bot tokens stay on coordination when Cursor, Hermes, and ChatGPT do their own work in their own context.

The test that matters is the phone message, the tagged worker, the pull request, the merge, and the result in the same thread.
